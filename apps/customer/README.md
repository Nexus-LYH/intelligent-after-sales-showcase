# 客户门户（当前至第七批）

沿staff既有Vue/TypeScript/Pinia/Element Plus版本和锁文件，各自`npm ci`、`npm run typecheck`、`npm run build`。本应用复用同仓库staff的认证/API/scope及公共壳源码，Vite去重Vue/Router/Pinia，TypeScript映射本应用依赖，不另造认证协议。

开发先在本目录`npm run dev`，仅loopback5180作为内部转发；再在apps/staff运行dev，浏览器唯一入口`http://127.0.0.1:5173/customer/`。员工入口`/staff/`，两个入口的`/api`统一由5173代理gateway8080，禁止绕回直连identity或把5180作为浏览器另一个Origin。HMR同样通过5173/customer路径。构建产物为本目录dist，base=/customer/。

路由：/login、/account、/account/password、/devices、/devices/:id。首次强改密完成后显式重新登录，再查授权企业及设备；员工/平台误入只显示适用入口和显式退出，不加载客户正文。企业事实来自asset当前有效成员关系，不来自identity/me或客户端companyId。设备只读，停用保留说明；无创建/修改/报修/工单入口。

保留首次login→me（接收更换Cookie）→AUTH csrf串行，以及generation/身份attempt/组件alive/请求slot归属检查。密码与CSRF不持久化，未知不自动重发。共Cookie的单浏览器上下文只有一个当前账号，管理员/客户验证必须独立上下文。

`npm run browser`为真实Chrome配合合成HTTP的两应用UI验证；不连接数据库，不等于真实gateway联调。真实联调证据以协作记录/前端开发顾问-沟通记录.md及第四批前端运行证据为准。当前公开契约见开发者设计/登录与会话最小契约草案.md第14节。无推送部署。

## 第五批追加范围

授权且当前启用的设备详情增加报修入口：`/repairs/new?deviceId=...`；另有`/submissions/:operationId?`（标题“报修提交结果”）、`/tickets`本人列表及`/tickets/:id`本人详情。该节取代上方第四批“无报修入口”的历史范围；客户首页仍保留授权设备，不扩企业管理员或工单处理。

一次报修UUID同时约束附件submissionId；每个上传另有UUID。上传先真实READY，全部文件就绪才提交。首次提交冻结原参数/附件集合，网络或5xx未知后保持原UUID、File与摘要；只查询，不自动恢复或换键。同设备未决动作须先回原结果页；404只表示当次未见，只有内存中保留原参数时才提供用户显式原键原参重交。服务端已登记操作用空JSON显式resume。刷新只凭URL中的非秘密原UUID重新授权查询，不重建丢失的正文/联系人/文件。

只有明确ABORTED后允许终止处理；旧未引用附件须显式删除，新提交需要重新上传，不迁移fileId。上传未知按原上传UUID查询，明确FAILED后才可同键同文件显式重试；UPLOADING/UNKNOWN不能直接当作移除成功。正常表单离开提醒，业务草稿只在当前标签页内存按actor/namespace保留，另一身份看不到原内容。

新增附件预览/下载每次重新授权与在线对象核验，回调受generation/attempt/组件/路由/slot和原动作保护。最终验证状态及窗口占用看前端沟通记录与第五批运行证据，构建、合成Chrome、真实服务Chrome、独立验收分别记录，不互相替代。


ID-05补充：查询原上传404 TARGET_NOT_ACCESSIBLE显示“本次未观察到原上传”，可在保留同一File/摘要/设备参数和原两个UUID时显式原键同文件重传；不将404解释为绝对未执行，不允许直接丢弃未知附件。401/403/503不会开放该分支。恢复规则和验证命令见staff README的ID-05节及本角色沟通记录。

## 第六批真实状态与公开时间线

本人列表/详情同步待受理、待分派、待本人接单、处理中及已驳回真实状态；处理中明确不等于设备修好。仅显示服务端当前本人/成员授权投影的CUSTOMER_VISIBLE时间线与处理记录，不显示内部正文、工时、资格快照、内部计数；异常夹带内部记录/工时时停止显示并显式重新核验。旧身份/attempt/组件回执仍隔离。没有客户受理/派工/记录写入及解决关闭入口。共享组件和第六批验证脚本位于staff，按其README及本角色沟通记录执行，合成与真实证据不混用。

## 第七批当前方案、确认与同轮反馈

本人详情显示真实当前方案/各次尝试、已确认累计工时、公开决定和关闭说明。仅服务端返回customer-confirm/customer-return且当前原报修人NORMAL时展示动作；未解决必填理由，退回不换轮次，新方案须重新决定。旧方案不再提交，旧未知原UUID只保内存供查询。确认仅表示RESOLVED/等待客服核验关闭，CLOSED后只读，不开放重开/评价等按钮。计时取服务端事实，72小时不自动满意或关闭，不展示内部处理记录/资格或核验秘密。详情/记录/方案/原结果/附件仍须当前对象权限，不靠隐藏按钮授权。


## 第八批当前补充请求与私有回复附件

本人详情显示当前OPEN补充问题及公开历史。仅服务端allowedActions包含supplement-reply且当前NORMAL原报修人时显示回复；同企他人/员工不可代回复，服务端仍逐次核验快照企业当前成员。回复仅恢复待受理/处理中，不代表已受理或修好。新的补充请求不复用旧正文、原UUID或附件。

可选0～5份PNG/JPEG/PDF私有附件（每份20MiB）；上下文为当前ticket/round/request/拟回复UUID，不用新报修设备当前归属版本。未知上传先查原UUID，404仅本次未观察到，显式同UUID同File同摘要重传；401/403/503不放行。未知回复保留原正文/文件/UUID，不自动提交、删除未知附件或换键。旧请求只读查询区保留原操作和原件，不挪用到新请求。已引用补充附件由双方当前工单授权下载，并校验摘要。

双72小时累计预算、当前等待及首交原始/有效历时均取服务端事实，额度耗尽不自动恢复状态/确认/关闭，不显示假提醒。共享实现/验证脚本位于staff；构建、合成Chrome、真实最终四JAR及独立验收分层，以前端开发顾问沟通记录为准。

补充上传查询到明确FAILED后，可显式原键重传或显式移除未引用文件（须等服务端删除回执）；非READY的大小/类型可尚未生成。查询404只表示本次未观察到，仍不能据旧失败状态直接丢弃未知文件。


## 第九批普通维修取消

原报修人按服务端allowedActions进行未受理直接取消或受理后申请；受理前补充已有首响不等于已受理。staff审核同时需要显式ticket.cancel.review、ticket.read与服务端当前企业范围。待审独立显示，不改变主状态、不停止工程师责任或计时；拒绝展示当前服务端状态，提交时历史状态仅供参照。

直接取消原因可选，申请/审核公开理由5～500码点；预览明确确认，修改后重新确认。未知保原UUID/完整参数，404仅本次未观察到，显式同键恢复；版本/当前申请变化或CANCELLED后旧操作仅查询，迟到回执与finally按身份代际/attempt、组件/路由及操作owner隔离。

取消后停止处理/补充/客户方案决定入口，终止历史不伪造回复或CONFIRM；历史、已引用附件按当前权限读取，未知附件仍保留。终结计时与两类扣除取服务端冻结事实，取消不计已解决。只支持普通维修本地原子取消，不宣称库存费用清理、外部取消、转派或重开。

契约19 B9-1为准：申请动作回执state=PENDING_REVIEW，申请cancellationState=PENDING_REVIEW；审核回执decision=APPROVE/REJECT，历史decision.decision=APPROVED/REJECTED/NO_LONGER_APPLICABLE；取消事实适用摘要为check.scope/relatedWorkflows。scripts/batch9-*在staff目录，构建/单元、全量拦截API的Chrome合成、默认最终四JAR真实联调及独立验收分层。真实脚本仅在共享记录明确交接最终制品/窗口后设置IAS_BATCH9_RUNTIME_CONFIRMED=1运行；脚本存在不代表已验。
