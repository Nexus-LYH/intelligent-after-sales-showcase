# Stock: persistent inbound and authorized catalogue prerequisite

Owner: technical lead/root acting as BE-S. This directory is isolated from B11 and is not in the shared reactor yet; BE-0 alone integrates the parent POM and trusted routes.

`InboundLedger` executes a real JDBC transaction: current access port, enabled tenant-owned warehouse/part locks, balance increment, immutable idempotency receipt, movement and audit. A failed audit rolls all writes back. The connection must be dedicated, begin in auto-commit, and use a UTC database session. On failure the transaction is rolled back; rollback uncertainty aborts the connection without restoring auto-commit. No public endpoint accepts tenant/actor/authorization assertions. A future trusted adapter must validate current warehouse permission and private evidence ownership; no permissive production adapter exists here.

Migration `V1__stock_inbound.sql` creates tenant-keyed warehouse/part/balance and inbound facts. The original PRD allows multi-part applications in one warehouse; this inbound command describes one delivery line only and does not restrict future reservation applications to one part. Quantities use integral BIGINT with overflow rejection; available stock remains on-hand minus reserved.

Database tests use real in-memory H2 JDBC in MySQL mode and do not use or restart MySQL3307. Three additional fault tests wrap those real connections and inject commit/rollback/abort exceptions through a connection proxy; their DataSource factory uses Mockito. These are controlled exception tests, not physical network/power faults. They establish transaction/rollback, receipt uniqueness and concurrency on H2; they do not establish MySQL locking/migration behavior. The SQL has not been applied to 3307, and no table/role/database has been created there. Uncertain commit or rollback connections are aborted without calling pool-wrapper close; if abort also fails, the reference is quarantined and this ledger fails closed until operator reconciliation. A production connection disposal/eviction adapter remains an integration prerequisite.

## 14.18 catalogue runtime (2026-10-21)

`StockApplication` is a Boot application on loopback 8445, with TLS/edge configuration provided by BE-0. It refuses startup without `IAS_CHAIN_CONFIG` role `stock`. The service datasource uses external `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`; TLS uses existing external Spring configuration. Do not put credentials in this directory. SQL automatic initialization is disabled. Migration owner must apply V1 then V2 once to a dedicated stock schema. Runtime minimum catalogue grants are SELECT on warehouse/part/balance; the separate initialization operator also needs SELECT/INSERT/UPDATE on initialization receipts and INSERT on warehouse/part. Neither catalogue endpoint writes.

Public and internal contracts are frozen in `api-catalog-v1.json`. Public requests must come through gateway-stock. `TrustedStockAccess` uses current stock-identity domain authorizations and stock-ticket CATALOG context, checking freshness, current IN_PROGRESS assignment, tenant and engineer identity. Balance reads require explicit current warehouse scope; an engineer selector exposes metadata only. The internal approval check uses approval-stock, derives identity online, and validates enabled tenant-owned catalogue objects. The approval caller separately validates the ticket relation. All replies use no-store. Missing trust or dependency failure grants nothing.

The controlled initializer is a separate CLI, not an HTTP account/catalog management interface. Its `IAS_STOCK_BOOTSTRAP_CONFIG` is a restricted external Java properties file with keys `jdbcUrl`, `user`, `password`, `permittedTenantId`, `operatorReference`. Only loopback MySQL3307 and schema names starting `ias_stock_` are accepted. Use a dedicated physical connection, never a pooled connection. It does not read browser claims, grant warehouse scopes, create balances, or manufacture inbound evidence. Generated positive BIGINT IDs are returned as strings. It initializes one catalogue per permitted tenant; reusing the original operation UUID and unchanged plan returns the original receipt. A changed plan conflicts. Concurrent first-attempt losers roll back and must retry the unchanged plan. Commit uncertainty requires reconciliation via that original plan, never a replacement UUID.

Plan file shape (nonsecret): `{"operationId":"canonical UUID","warehouses":["Main"],"parts":[{"code":"FILTER_1","name":"Filter","model":"M1","unit":"pcs","safetyStock":0}]}`. Names are bounded; part codes are already normalized uppercase. No tenant or IDs occur in the plan. From an assembled application dependency classpath invoke `com.ias.stock.StockCatalogBootstrap <plan.json>`; alternatively the Boot executable supports `java -Dloader.main=com.ias.stock.StockCatalogBootstrap -cp target/stock-0.0.1-SNAPSHOT.jar org.springframework.boot.loader.launch.PropertiesLauncher <plan.json>`. Bootstrap emits only its nonsecret receipt, and generic errors without connection details. The operator must preserve the plan and original UUID for unknown-result recovery.

Current validation: 24 actual isolated-module tests passed (original 12 inbound, 6 catalogue/cache, 3 trusted adapter, 3 initialization). These are H2/JDBC and controlled adapter tests. No live MySQL migration, actual TLS/HTTP/browser chain, or independent business acceptance has been performed for these additions. Shared ports/services were not started or occupied.

Outstanding: private inbound evidence reference lifecycle and production inbound access adapter, MySQL/runtime migration and least-privilege test, complete application reservation/expiry/dispatch/consume/return flows, paid execution generation barriers, inventory count/review/reconciliation, domain outbox integration, browser and independent acceptance. Inbound success is not reservation or parts execution approval. This slice must not be presented as FR-STOCK-01–04 complete.

## 2026-10-22 real inbound slice
API contract: inbound-api-v1.json. Current warehouse read/manage capabilities are resolved online; write CSRF is checked at gateway and stock. Stock owns immutable private evidence in stock_evidence (not ticket attachments); explicit upload UUID and digest prevent conflicting retries, and current warehouse permissions apply to metadata/download/new Range. Inbound original query is pure and actor bound. V3/V4 add transactional inbound outbox and private evidence; event delivery, retention cleanup, reservation, issue, use and return remain separate unfinished scope. Do not enable a stock consumer or delete retained evidence based on this slice. Runtime immutable operation/movement/audit/outbox/evidence tables need SELECT/INSERT only, balance needs quantity/version column UPDATE; catalog active-column UPDATE is required only for existing InboundLedger FOR UPDATE serialization. No catalog edit API is exposed. Read the local operation evidence and current process ownership before replacing a running JAR; old CI does not cover this increment.
